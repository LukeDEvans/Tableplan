- 2026-09-20 · **[FIXED in scripts/check-boot.mjs]** `npm run boot:check` failed outright in a cloud sandbox — both launch attempts missed: `channel: "chrome"` (no system Chrome there) then plain `chromium.launch()` (Playwright 1.54, pinned in package.json for local Node 18 compat, looks for its own bundled revision `chromium_headless_shell-1181`; the sandbox's pre-staged browser is a different revision, e.g. `chromium-1194`, reachable only via the stable version-independent symlink `$PLAYWRIGHT_BROWSERS_PATH/chromium`). Not a stale version pin and not a missing `npx playwright install` step (that would fight the sandbox's own provisioning, which deliberately pre-stages a browser instead of downloading one) — it was `launch()` simply not knowing that fallback path existed. **Real fix**: `launch()` now tries system Chrome → Playwright's own managed Chromium → `executablePath: "$PLAYWRIGHT_BROWSERS_PATH/chromium"` (checked with `existsSync` so it's a no-op locally) before giving up. Separately, that Chromium then failed EVERY navigation, including `http://localhost`, with `net::ERR_CERT_AUTHORITY_INVALID`/`ERR_TUNNEL_CONNECTION_FAILED` — it inherits the sandbox's `HTTPS_PROXY` env var and tries to tunnel local traffic through it too. Fixed by always launching with `args: ["--no-proxy-server", "--proxy-bypass-list=*"]` (harmless no-op on a machine with no proxy set). Verified: `npm run check:boot` now passes for real in this same cloud sandbox (build + boot + Weather/Contacts smoke, no substitute probe) · Live/Tableplan
