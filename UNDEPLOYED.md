# Undeployed changes

Work merged to `main` that is **not live yet**. Merging no longer deploys: a production
build runs only when the merge (or a later commit on `main`) has **`[deploy]`** in its
commit message (`scripts/netlify-ignore.sh`). When you deploy, run
[PRE_PUSH_CHECKLIST.md](PRE_PUSH_CHECKLIST.md), do the post-deploy steps below, then
empty this list.

Each entry: what shipped · PR · post-deploy steps.

---

_Last deploy: 2026-10-06 (PRs #51–#56)._

- **Page notifications: a thin red underline under the page title, not a red dot** · PR #65 · On the home links, the page-title menu and Recreate's Travel card, a page with notifications now has its title underlined in thin red; the dot is gone. The Tasks bell and the mini-player art have no title and keep their dot. CSS only. Reaches the phone **only via a TestFlight build**. Post-deploy: with a Mail suggestion or an unlabeled Finance transaction pending, Home and the page-title menu show that page's name underlined in red with no dot, and the underline clears once the item is addressed.

- **Mini-player: no rewind 10 seconds button** · PR #66 · The back-10-seconds button is gone from the dock's mini-player, so the title and show name get its width (about 58px more on a phone). Rewind is still in the Now-Playing window. Reaches the phone **only via a TestFlight build**. Post-deploy: with audio playing, the mini-player shows only play/pause on the right and the title runs wider; open Now Playing and confirm its skip buttons still work.

- **Finance notifications window: same size as Meal Plan's, close button reachable** · PR #64 · Fixes a fault from PR #54 (live since the 2026-10-06 deploy): the Finance notifications window opened at the very top of the screen, putting its close button under the phone's status bar. It now opens in the standard notifications-window box (`notificationsWindowBox()`, dock-space.js), the same place and size as Meal Plan's. Reaches the phone **only via a TestFlight build**. Post-deploy: Finance → bell: the window sits inside the page window and the ✕ closes it. A review card is taller than the window on a phone (ISSUES.md): scroll the card, or swipe right to approve.

- **Dock: one standard blue for every slide; wind and UV on the weather slide** · PR #63 · The dock is now the same blue everywhere (the weather slide's night blue, `--dock-bg1`/`--dock-bg2` on `.bottom-dock`) with white text, in the light and dark themes. The mini-player takes it: white title, controls and progress line. The weather slide no longer changes colour with the weather. It has a new third line with wind speed and direction and the UV index; either one is left out when its reading is missing. CSS and `weather-ui.js` only. Reaches the phone **only via a TestFlight build**. Post-deploy: the dock is blue with white text on both slides, with audio playing and with nothing playing; the weather slide shows "Wind … · UV …" under the place name and nothing is cut off on the phone; with a weather alert showing, all four lines fit.

- **Notifications windows: never open with nothing in them** · PR #62 · The standard for every bell (CLAUDE.md, UI conventions): an empty bell does not open its window ("You're all caught up." toast), and the window closes by itself when the last item is addressed. Applies to Meal Plan recipes, Recipe Box review, Mail suggestions, Explore proposals and Finance's review deck (which loses its "All caught up" screen). Reaches the phone **only via a TestFlight build**. Post-deploy: Meal Plan → bell with no badge: nothing opens. With recipes: add or dismiss the last one and the window closes. **Mail** and **Finance** were not checked before merge (ISSUES.md): clear the last suggestion / the last review card and confirm each window closes and the page behind it is up to date.

- **Meal Plan notifications: no scrollbar on the side** · PR #61 · The recipe-notifications window (list and cards) no longer shows a scrollbar; it still scrolls. CSS only. Reaches the phone **only via a TestFlight build**. Post-deploy: Meal Plan → bell with several new recipes: no scrollbar down the side, and swiping up still moves to the next card.

- **Mail: emails no longer render as overlapping, unreadable text** · PR #60 · **Fix:** with remote images blocked (the default), every email lost its own stylesheet, so phone layouts never applied, the email was shrunk to fit, and the iPhone then enlarged the text past its line spacing. The stylesheet is now kept, the frame stops the iPhone from resizing text, and a wide email is no longer shrunk twice. No state changes. **After deploy:** (1) fully close and reopen the app; (2) open "This week in Claude Code" (Oct 3) on the iPhone: text should fill the pane with normal line spacing (the iPhone itself was not available to test on); (3) open a few other newsletters with images still blocked and check none is tiny or clipped at the right edge.

- **Media: the reader's Play button plays the open article; an add while the queue plays is reached** · PR #59 · **Fix:** with another article loaded (or, in the iPhone app, a podcast playing), pressing Play in an open article resumed that other audio. It now starts the article that is open, and the button shows Pause only while that article is the one being read. **Fix:** "Add to queue" while the queue was already playing put the item in the list but playback never reached it, because the queue plays from the order captured when it started. The add now joins that running order (and the iPhone app's up-next list). No state changes. **After deploy:** (1) fully close and reopen the app (or install the new TestFlight build) first; (2) play any article, open a different one, press Play: the second one should start; (3) on the iPhone, with a podcast playing, open an article and press Play (the native path was read from code, not run on a device); (4) with the queue playing, add an older episode and let the queue run to it.
