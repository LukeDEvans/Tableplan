# Undeployed changes

Work merged to `main` that is **not live yet**. Merging no longer deploys: a production
build runs only when the merge (or a later commit on `main`) has **`[deploy]`** in its
commit message (`scripts/netlify-ignore.sh`). When you deploy, run
[PRE_PUSH_CHECKLIST.md](PRE_PUSH_CHECKLIST.md), do the post-deploy steps below, then
empty this list.

Each entry: what shipped · PR · post-deploy steps.

---

_Last deploy: 2026-10-06 (PRs #51–#56)._

- **Shop: the checklist can no longer be erased by a sync; Inventory is a tab of Shop** · PR #PRNUM · (1) **Fix (data loss):** the Shop checklist's item list merged as "the newer copy wins", so a device holding an empty list (fresh install, old tab, a boot before the cloud copy arrived) erased the household's list as soon as it saved anything. This happened on 2026-10-01 to all 22 items. The list now merges by id: an item leaves only when it is removed (the removal is recorded), never because one copy lacks it (`mergeChecklistConfig` in grocery-sources.js). (2) Inventory is a space of the Shop page: the title stays "Shop", it shows Shop's date header instead of today's date, it has no window frame, and the three tabs sit in the same place on all three. Switching Inventory → Shop no longer counts as opening Shop (no sweep). No new state keys. Reaches the phone **only via a TestFlight build**. **After deploy:** (1) fully close and reopen the app on every device; (2) **restore the checklist** (ISSUES.md, P1): it is still empty in the cloud, and the 22 items are in `tableplan_state_history`; (3) Shop → Inventory: title and date header don't change, no border.

- **Shop: checked items are swept on open, no window frame, bought manual items stay gone** · PR #67 · (1) Opening Shop sweeps everything checked into "bought" (what the broom does) and closes any "Show N bought" reveal, so the list opens on what is left to buy; "Show N bought" still brings them back, and un-checking one restores it. (2) The Shop window has no navy border, shadow or inner buffer, and the list's own gutter is 10px instead of 16px: about 36px more width on every screen. CSS only; Inventory keeps its frame. (3) **Fix:** a manually typed item that was checked off came back unchecked each new shopping cycle (every Friday) and whenever the date range was changed, because checked / bought marks are kept per cycle while the manual list is permanent. Now a manual item checked off in a cycle that has ended is taken off the manual list for good the next time Shop is opened (a stamped removal, so it survives a sync), and one checked off in a cycle still ahead stays under "bought". Typing an item in again clears its old marks. Only marks from the cycle ending 2026-10-09 onward count, so nothing already on the list is removed by this change (`grocery-bought.js`). No new state keys. Reaches the phone **only via a TestFlight build**. **After deploy:** (1) fully close and reopen the app; (2) Shop → check an item, go Home, open Shop: it is under "Show 1 bought", not on the list; (3) the Friday after, open Shop: manual items checked off that week are gone, unchecked ones are still there, meal-plan items are back as usual.

Post-deploy: with a Mail suggestion or an unlabeled Finance transaction pending, Home and the page-title menu show that page's name underlined in red with no dot, and the underline clears once the item is addressed.

No state changes. **After deploy:** (1) fully close and reopen the app; (2) open "This week in Claude Code" (Oct 3) on the iPhone: text should fill the pane with normal line spacing (the iPhone itself was not available to test on); (3) open a few other newsletters with images still blocked and check none is tiny or clipped at the right edge.

No state changes. **After deploy:** (1) fully close and reopen the app (or install the new TestFlight build) first; (2) play any article, open a different one, press Play: the second one should start; (3) on the iPhone, with a podcast playing, open an article and press Play (the native path was read from code, not run on a device); (4) with the queue playing, add an older episode and let the queue run to it.
