- [ ] **[P1] Months backfilled by the OLD CSV import show $0 per category in the Budget view** (finance · finance-ui.js applyCsvMonthBackfill · 2026-09-26)
      `aggregateCsvBackfill` keys `cats` by the full label (`"cat:<gid>:<cid>"`), but every reader — the budget month view (`catActual` → `` `${g.id}:${c.id}` ``), last-month compare, draft-from-history per-category lookups — and the live snapshotter use `"<gid>:<cid>"`. Suggested: a one-time, idempotent normalizer (strip the `cat:` prefix, summing any collision) — a finance-state data repair, so it needs Luke's OK. Verdict: CONFIRMED by reading + test.

- [ ] **[P2] A swipe and a concurrent mail sweep can race on the news pending row** (mail · _news-links.js saveNewsBatch/removePendingNews · 2026-09-27)
      Both do read → modify → write of `mailnews_<user>` without a version check. If a sweep's batch write lands between a resolveNews read and its write (or vice versa), one side's change is lost: either a just-swiped card reappears once (it can't be re-delivered later — the seen record is separate and unaffected), or a newly-collected card is dropped from the deck. Same pattern as the recipe pending row. Suggested if it's ever noticed: route both through `_state-sections.updateSection`-style optimistic locking on `updated_at`. Verdict: PLAUSIBLE (timing window is small; sweeps are ≥30s apart).
- [ ] **[P2] SimpleFIN reconnect could re-ingest the same charges under new ids** (finance · FINANCE_TRANSACTIONS_DESIGN.md §2 · 2026-09-26)
      The durable `finance_transactions` store is keyed by the bank's txn id (the same id the JSONB annotations use). If SimpleFIN is disconnected/reconnected and the institution issues new account/txn ids, the next ingest inserts the same real charges again under new ids → duplicates in the list and (for the live window) in actuals. `reconcilePending` only handles pending→posted, not id reissue. Suggested: a "reconnect remap" tool (match old↔new by account+date+amount+merchant, carry annotations across, mark old rows superseded). Out of scope for the store project by decision. Verdict: PLAUSIBLE (depends on the institution), not yet observed.
